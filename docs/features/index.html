Windows, macOS, Linux, or just Fabric Notebooks

Turn a SQL query into a working table

Give Weaver a SELECT and a key. It creates the table and loading steps, tracks changes and records the results.

Turn Python and SQL into Lakehouse tables

Use Python and Spark SQL to load files and update Delta Tables, without building a separate orchestration project.

Find what depends on what

Weaver can read dependencies from Python imports and supported T-SQL references. With Spark SQL, you specify them.

Load only what has changed

Apply inserts, updates and explicit deletes using rules you choose, without rebuilding every target.

Pick up where each table left off

Each table or folder tracks its own progress through the source data, even when several share the same source.

Test data and calculations

Compare actual and expected results or find invalid rows using Python, SQL and DAX.

Data-quality safeguards

Keep rejected rows and stop unusually large proposed updates or deletes before they reach your tables.

Built for scale

Tuned for each engine

From Delta reads and writes to transactions, T-SQL and Shortcut creation, each operation is tuned for its engine to eliminate waste.

Run independent steps together

Weaver can run separate Spark and Warehouse steps at the same time, within limits you choose.

Process only the changes

Each object tracks its own progress, so it can process inserts, updates and deletes rather than starting over every time.

SQL endpoints refreshed as needed

A refresh runs in the background, and only the consumers that need the new state wait for it.

Visibility, included

Weaver includes a Power BI dashboard showing the status of your work. One command adds it to your Fabric workspace.

One command

weaver catalogue-dashboard deploys the semantic model and Report beside the catalogue, and brings them up to date on the next run.

Live over Direct Lake

The model reads the catalogue’s tables over Direct Lake, so each page shows your Weaver-managed estate as work is processed.

Free to tweak

It is an ordinary Power BI Report. Tweak it to fit your needs, or throw it away and build your own over the catalogue.

When your projects get more complex

One project, multiple environments

Keep source files and logical identities while workspace configuration selects physical item and model destinations.

Update only what changed

See changes before applying them

Review deployments before applying them
