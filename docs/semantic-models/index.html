Semantic models in the same Fabric project.

Deploy native TMDL models alongside the Lakehouse and Warehouse data they use. Share conventions and validate the results.

Keep your native model

Build deploys the model and its linked Report from a PBIP project. Workspace configuration chooses the physical targets; your authored files stay in source control.

Deploy a model and Report →

Connect refresh to source data

Managed source dependencies connect the model to its Lakehouse or Warehouse Tables. Load refreshes it after selected source work, and Health includes its refresh and validation state in the estate report.

Connect the model to its source →

Apply modelling conventions once

Use a native TMDL overlay to hide many-side relationship keys:

PowerBI/Parcel/Parcel.tmdl 
model Model
    annotation 'Weaver.AutoHideForeignKeys' = true

Share formatting and calculation structures through policy. A custom Python annotation can apply a project-specific rule when native declarations are not enough.

Test the model’s numbers

DAX Assumptions report violating rows. DAX-to-SQL Tests compare a measure with an independent calculation over its Lakehouse or Warehouse source.

Reuse a model foundation

Compose named variants from a shared base, then add measures, exclude tables or override formats for each output. Each variant has its own Report and validations.
