Keep writing Python and Spark SQL.

Weaver handles the deployment, dependencies and processing state around your Lakehouse code, so each Table does not need its own surrounding pipeline.

A file should not need an orchestration project

Read a carrier export into a Delta Table. Import the upstream Folder just as you would import another Python module:

Inside a Python Table: read the upstream Folder 
from Files.Parcel__Events import Parcel__Events
from weaver import Table

class Parcel__Event(Table):
    def read(self):
        source = Parcel__Events(self).spark_path()
        return self.spark.read.option("header", True).csv(source)

That import is also the load dependency. Weaver stages the Folder, installs the Table code and loads the files before the Table. The first tutorial supplies both complete definitions and finishes with three queryable parcel events.

Let the consumer remember its own progress

A changing source does not need to become another full reload. Each consumer keeps its own successful-processing bookmark; your Python or SQL chooses the changed rows and explicit deletions, and Weaver reconciles them with the target.

Connect the next item without a guessed delay

A Warehouse or model may need the Lakehouse data to be visible through its SQL endpoint. Weaver includes the supported publication and endpoint-readiness work in the selected dependency order, and records what completed or needs another run.
