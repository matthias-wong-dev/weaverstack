Lakehouse engineering in Python and Spark SQL.

Keep extraction and transformation in ordinary code. Weaver handles deployment, dependencies, incremental progress and recorded outcomes.

Files and Tables in the same project

An API export or a set of spreadsheets can feed a Delta table without another orchestration project. Declare the Folder and Table, then use a Python import to connect them.

Inside a Python Table: read the upstream Folder 
from Files.Parcel__Events import Parcel__Events
from weaver import Table

class Parcel__Event(Table):
    def read(self):
        source = Parcel__Events(self).spark_path()
        return self.spark.read.option("header", True).csv(source)

The tutorial supplies the complete Folder and Table definitions for this Python excerpt.

Keep incremental progress with each consumer

Each Table or Folder keeps its own successful-processing bookmark. Use it to read changes, then let Weaver apply inserts, updates and explicit deletions and record the outcome.

Develop against existing data

Mirror presents unchanged data through OneLake shortcuts. Build the parts you change locally while other Tables remain at their source.

Connect the Lakehouse to the rest of the estate

Weaver orders source loads and the Warehouse or semantic-model work that reads them. SQL endpoint readiness is part of that order, rather than a delay you maintain in a pipeline.

Health combines the Lakehouse’s recorded state with the rest of the managed estate. After a failure, use that report to find the work that needs another run.
