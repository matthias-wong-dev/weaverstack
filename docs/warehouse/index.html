Write the SQL. Weaver builds the load machinery.

A query and a declaration are enough to maintain a Warehouse Table. Weaver creates the structure, applies changes according to your load policy and records the result.

Keep the transformation as a SELECT

You should not have to write staging, key matching and row-change procedures again for each reference Table. Declare the identity, key and schema alongside ordinary T-SQL:

Warehouse/Operations/Parcel.Depot.sql 
/*
Table ID: Parcel.Depot
Description: Delivery depots.
Lineage: A small reference list authored in the project.
Primary key: Depot ID
Schema:
  Depot ID: int
  Depot: varchar(30)
*/
select DepotID as [Depot ID], Depot
from (values (1, 'North'), (2, 'South')) v(DepotID, Depot);

Build creates the physical Table and its loading procedure. Load stages the query result, reconciles the declared rows and records inserts, updates, deletions and rejects. Supported SQL references supply the dependencies; the query stays readable SQL.

Make the number testable

Put an independent expected result beside the transformation. A Test compares it with the actual rows; an Assumption finds rows that break a condition. Their results belong to the same operational state as the load.

Change the source once, not the machinery around it
