Your SQL, with the repetitive engineering already done.

Keep the query recognisable. Let Weaver handle the surrounding work of installing, loading and inspecting it.

Keep ordinary T-SQL

The transformation stays a query. Native comments hold its identity, keys and schema; there is no new macro language to learn.

Warehouse/Operations/Parcel.Depot.sql 
/*
Table ID: Parcel.Depot
Description: Delivery depots.
Lineage: A small reference list authored in the project.
Primary key: Depot ID
Schema:
  Depot ID: int
  Depot: varchar(30)
*/
select DepotID as [Depot ID], Depot
from (values (1, 'North'), (2, 'South')) v(DepotID, Depot);

Build creates the table and its generated load procedure. Load runs the query and applies the data. You do not hand-maintain a procedure for each table.

Develop against existing data

Mirror uses views to borrow unchanged Warehouse data. Materialise selected changed work in development without copying the whole Warehouse first. Borrowed data remains at its live source, not in a frozen development snapshot.

Install changes without blindly rerunning data

Build and Load are separate. Inspect a Build preview, install a definition change, then catch up affected data. Independent work can remain untouched.

Some changes replace physical structures; Build is not an in-place schema migration for every change. Protection and reconstruction have their own boundaries.

Make a change and inspect its result →

Know what is current

A green run yesterday does not establish freshness after upstream data changes. Consumer bookmarks, installed definitions, failed and blocked state, row movement and validation results are recorded in the catalogue.

Use that evidence to decide what to rerun instead of maintaining another set of status files.

Cross the Lakehouse boundary without hand-built waiting steps

When supported Warehouse work reads through a Lakehouse SQL endpoint, Weaver puts the relevant upstream work and endpoint-readiness waits in the run. You maintain the query rather than another waiting pipeline.
