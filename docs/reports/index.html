Reports deployed with their semantic models.

Keep one native Report project. Workspace configuration chooses the destination and its linked model in each environment.

One source, different destinations

Development and production can use different workspace and item names. Keep those mappings in configuration rather than maintaining publishing copies of the Report.

Development

workspace-dev.yml 
workspace: Parcel BI Development
targets:
  SemanticModel/Parcel: Parcel_Dev
  Report/Parcel: Parcel_Report_Dev

Production

workspace-prod.yml 
workspace: Parcel BI Production
targets:
  SemanticModel/Parcel: Parcel
  Report/Parcel: Parcel_Report

Deploy the model before the Report

Build deploys and verifies the selected semantic model first, then binds its linked Report to the resolved model target. The deployment payload changes; the authored project files do not.

Load refreshes the semantic model. The Report uses that data without a separate data-load step.

Deploy models and Reports →

Update a Report without rebuilding its sources

With a registered model, a Report-only Build can update the Report while retaining its model and data. The shared catalogue keeps the installation and binding with the rest of the estate.
