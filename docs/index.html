Build, load, test and inspect the estate

Build deploys definitions. Load runs data work and refreshes semantic models in dependency order. Test checks SQL, Python and DAX results. Health brings the recorded state together in one report.

The catalogue keeps definitions, dependencies, progress and outcomes in a Fabric Warehouse. You can inspect that state without assembling it from separate pipelines and log files.

How Weaver works →

The same source in development and production

Workspace configuration maps your project’s logical names to the right Fabric items. Change the configuration to deploy to another environment; keep the authored files in source control.

Mirror lets development use existing data through views and OneLake shortcuts. Only the work you change needs a local copy.

From a few objects to thousands

The same project structure works for a few source files or a large estate. On F64, a 3,000-object test estate loaded in about an hour, with later incremental loads under 15 minutes.
