One project for your Fabric data estate.

Weaver brings Lakehouses, Warehouses, Python, T-SQL, shortcuts and operational state into one engineered system. It derives dependencies from your code and runs the estate in order, so crossing a Fabric item or engine does not require another layer of orchestration.

Fabric does not stop at the item boundary

A Fabric data path rarely stops at one notebook or table. Files land in a Lakehouse, Python shapes them, a Warehouse reads them through a shortcut, and T-SQL carries the work on. Weaver keeps that chain together.

One graph across Fabric

Dependencies cross Lakehouses, Warehouses, Python, Spark SQL and T-SQL without becoming a second orchestration model. Weaver reads the graph from imports, SQL references and shortcut declarations.

Structure apart from data

weaver build deploys schemas, tables, views, shortcuts and load code. weaver load moves data. Structure can be deployed without moving rows in the same operation.

Projects that move

Your source names logical items. A small workspace configuration binds them to physical development or production targets, so object references do not change between environments.

Runs you can recover

The Catalogue records what is installed, how far each object loaded, and what failed or was blocked. The next run starts from known state rather than a reconstruction from logs.

The project does not repeat the execution order

Branch an estate without copying all its data

Mirror gives a development workspace the installed state of an existing estate, then lets you choose which Fabric items to materialise locally.

Borrow what has not changed

A mirrored Warehouse reads source rows through views; a mirrored Lakehouse uses OneLake shortcuts. The project code and Catalogue are local, while unchanged data stays where it is.

Diverge one item at a time

Build an item into a development target when you need to change it. Other items remain mirrored, and Weaver keeps their dependencies and operational state visible in the fork.

terminal
weaver mirror --no-item --yes
weaver mirror --item Warehouse/Model=Warehouse/Model_Dev --yes

These commands use the source and destination catalogues named by mirror: and catalogue: in the development workspace configuration.

Run the Sales example

Install Weaver, initialise the Sales project, then build, load, test and check its health. The walkthrough names the prerequisites and every command.

terminal
pip install weaverstack
weaver initialise --workspace Analytics
