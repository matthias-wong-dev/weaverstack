Familiar development, additional capabilities

Keep ordinary Python, SQL, native TMDL and Power BI projects. Weaver adds a small amount of organisation and configuration, then handles the repeated work around them.

One project across environments

Choose destination workspaces and item names through configuration rather than maintaining publishing copies.

Native deployed objects

Tables, views, semantic models and Reports stay native platform objects. Executing Weaver’s generated Python or annotations can still need Weaver.

Add only what helps

Start with ordinary deployment or loading. Shared rules, validation, selective recovery and composition are available when the problem calls for them.

Works with Power BI alone. Integrates with Fabric when needed. The standalone route still needs an appropriate service licence, access and permissions; free Desktop alone is not the deployment service.

Start small, stay organised

Two spreadsheets and a table over them are a project worth keeping in source control. Give their definitions a home, choose a target, and make the result repeatable. A team of one is a valid audience.

Source files can remain external to Weaver’s ownership. You do not have to hand lifecycle control to Weaver for data it cannot reconstruct.

Built for scale

From 3 objects to 3,000, keep the same way of working. A historical synthetic F64 run built 3,000 declared data objects from empty in 13m 48s; its first Load took 61m 20s. Those are source-estate results, not model or Report benchmarks.
