Built for scale

Thousands of objects. Hundreds of millions of rows.

Weaver is built for estates that run to thousands of objects across many Fabric items, and for tables that run to hundreds of millions of rows. The dependency model that runs a six-file example is the one that runs those, and it does not change shape on the way up.

What carries the weight

One graph, however wide

Every object in the estate sits in a single dependency graph, across Lakehouses, Warehouses, Python, Spark SQL and T-SQL. Ordering, layering and impact are all read from it, so adding items does not add coordination.

Builds do the work that changed

A build compares the repository against what is installed and touches the difference. A change to one object stops its descendants being certified, and nothing else moves.

Loads scale with the change

A keyed load classifies inserts, updates and deletes before it writes, and bookmarks mean an incremental object reads its window rather than its whole source. Cost tracks how much moved, not how much is stored.

State survives the run

How far each object loaded, what failed and what is behind its sources all live in the Catalogue. At this size that is the difference between an estate you can operate and one you can only rerun.
