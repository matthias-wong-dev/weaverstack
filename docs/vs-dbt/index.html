Weaver vs dbt

dbt manages data transformations. Weaver brings the wider Fabric estate into one project: Lakehouse files and Tables, Warehouse SQL, semantic models and Reports.

Differences that change the work

Lakehouse and Warehouse in one project

Weaver can put Python and Delta work in a Lakehouse, T-SQL in a Warehouse and the shortcut between them in the same project.

dbt uses separate Fabric adapters for Warehouse and Spark work. The order between the two has to be managed elsewhere.

Dependencies from ordinary Python and SQL

Weaver reads Python imports and supported T-SQL references. Spark SQL Tables and Views declare their dependencies explicitly; they still use native SQL rather than a macro layer.

dbt uses ref() and source() to declare those relationships.

Build the structure without loading the data

weaver build creates or changes tables, views, shortcuts and load code. weaver load runs the data work separately.

A dbt model is created and populated by the same run.

Run results stay in Fabric

Weaver records installed definitions, load and model-refresh outcomes, validation results and consumer bookmarks in a Fabric Warehouse.

dbt Core writes files such as manifest.json and run_results.json. State comparison uses a previous manifest.

Branch the Fabric data with Mirror

Weaver can give a development project the current production data without copying every table. Build the parts you need to change and leave the rest behind views or OneLake shortcuts.

dbt-fabric documents table cloning within one Warehouse. Mirror works across the Lakehouses and Warehouses in the Weaver project.

Native semantic models and Reports

Weaver deploys PBIP/TMDL definitions, applies shared modelling rules, binds Reports to their model and runs DAX validations.

dbt does not deploy native Power BI models or Reports. Its Power BI connector queries the dbt Semantic Layer; it is a different integration.

Where each tool fits

dbt is built around transformation models across many data platforms. Weaver is built around the Microsoft Fabric estate, from source loading and transformation to native model and Report deployment and their operational state.
