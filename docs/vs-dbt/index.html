For dbt developers working in Microsoft Fabric

Keep the code-first approach. Go further in Fabric.

You already know the appeal of defining data models in code. Weaver takes that approach across more of Microsoft Fabric: Python data loading, Lakehouses, Warehouse SQL, native Power BI, testing and the work that connects them.

More of Fabric, less work joining the pieces

One project from source data to Power BI

Load files and APIs with Python, build Delta Tables in a Lakehouse, write T-SQL in a Warehouse, then deploy native Power BI models and Reports. Weaver connects the supported steps in the right order.

Keep your SQL looking like SQL

Write an ordinary Warehouse SELECT. Weaver creates the table and loading code around it, including staging, key-based updates and recorded row changes. Python and supported SQL references also help establish what depends on what.

Build first. Load when you're ready.

weaver build deploys tables, views, shortcuts and loading code. weaver load runs the data work separately. Preview proposed changes before applying them, or run only the parts you need.

Develop with the data already there

Mirror can use existing Warehouse and Lakehouse data through views and OneLake shortcuts. Make local changes to the parts you're working on without copying every table into development.

Know what ran, what changed and what failed

Weaver keeps definitions, dependencies, load results, tests and progress together in a Fabric Warehouse. Run weaver health to see what's up to date and what needs attention.

Take native Power BI all the way to deployment

Use PBIP and TMDL, apply shared or model-specific rules, unit test DAX measures against independent SQL results, and deploy Reports connected to the right semantic model.

Build it. Load it. Test it. Know where it stands.

Deploying a table, loading its data and checking the results are separate steps. Run just the one you need. Here is the workflow for a Warehouse item:

From a configured Fabric project
weaver build --item Warehouse/Operations   # Deploy its definitions
weaver load Warehouse/Operations           # Run the data work
weaver test Warehouse/Operations           # Check the results
weaver health                              # Inspect the whole project
